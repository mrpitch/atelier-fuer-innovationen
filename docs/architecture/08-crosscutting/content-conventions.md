# Content Conventions and Validation

Content Sources, Content Validator and CI/CD Workflow share one contract: every Markdown or MDX file carries a `type` frontmatter field.

## Rules

| Rule                                                                                                                                                                                                                                                                                             | Enforced by                                                     | Scope                                        |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------- | -------------------------------------------- |
| Every `.md` and `.mdx` file has a frontmatter block with `type`                                                                                                                                                                                                                                  | `scripts/validate-okf.ts` (`pnpm validate:okf`)                 | Whole repository, minus the exemptions below |
| Content pages also carry `title` and `description`                                                                                                                                                                                                                                               | Convention in [README](../../../README.md); not machine-checked | `src/content/docs/`                          |
| Every `<Illu>`/`<Slide>` slug resolves to a registry entry, every `illus.json`/`slides.json` asset exists under `public/`, every `meta.json` `pages` entry resolves to a page, and every relative image or link in MDX resolves to a file                                                        | `scripts/validate-content.ts` (`pnpm validate:content`)         | `src/content/docs/`, `src/data/`, `public/`  |
| A page appears in the sidebar only when its slug is in the section's `meta.json`                                                                                                                                                                                                                 | Convention; Fumadocs ignores the rest                           | `src/content/docs/**/meta.json`              |
| Every protected text block (page title, heading, paragraph, list item, table cell, quotation) recorded in the baseline still exists verbatim somewhere in the tree; a block marked `{/* editorial */}` is exempt — see [glossary](../../reference/glossary.md#protected-copy-and-editorial-text) | `scripts/copy-integrity.ts` (`pnpm validate:copy-integrity`)    | `src/content/docs/xeniapolis/`               |

## Exemptions

The validator skips these without checking them:

| Exempt path                                                                 | Reason                                             |
| --------------------------------------------------------------------------- | -------------------------------------------------- |
| `node_modules/`, `.next/`, `.source/`, `out/`, `.git/`                      | Build and vendor output                            |
| Any `README.md`                                                             | Not a concept document                             |
| `docs/index.md`, `docs/agents/docs-context.md`, `AGENTS.md`, `CLAUDE.md`    | Loaded or generated by tools with their own format |
| `.claude/skills/`, `.agents/skills/`, `.sandcastle/`, `docs/audit-reports/` | Tool-owned frontmatter                             |

## When it runs

`.github/workflows/main.yml` runs job `validate-okf` (`pnpm test`, then `pnpm validate:okf`) on every push to `main` and every pull request targeting `main`, whether or not Markdown changed. Job `deploy` needs it (and job `quality`), so a failed validation stops the deploy. See [RISK-03](../11-risks/risks-and-tech-debt.md).

Job `validate-content` runs `pnpm validate:content`, job `validate-stadtviertel` runs `pnpm validate:stadtviertel` (the Stadtviertel data in `src/data/stadtviertel.json` against each Stadtviertel's `meta.json`, the section order and the icon names), job `validate-copy-integrity` runs `pnpm validate:copy-integrity`, and job `build-check` runs `pnpm build` and fails on the pinned missing-image warning strings, all on every push and pull request. Job `deploy` needs all six check jobs.

`pnpm test` runs `tsx --test scripts/*.test.ts`. It covers the validator and the other scripts, not the application — `scripts/copy-integrity.test.ts` also asserts the checked-in `scripts/copy-integrity-baseline.json` against the current tree, so an edited protected block fails `pnpm test` too, not only CI.

Regenerate the baseline after a legitimate content change with `pnpm generate:copy-integrity-baseline`, then review the diff: a shrinking or reworded baseline for an unrelated page is a sign the change touched protected copy by accident.
