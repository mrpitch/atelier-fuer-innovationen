# Setup Operation

**When**: First use of the `diataxis` skill in a new project, or when the project structure has significantly changed.

## Purpose

Scan the current project and populate `docs/agents/diataxis-context.md` with accurate, project-specific values so all other Diataxis operations use the correct commands, stack, and conventions — without containing hardcoded project assumptions.

**Write target is the consuming repo, never this skill's own install directory.** `docs/agents/diataxis-context.md` is resolved relative to the current working directory (the same convention `setup-my-skills` uses for `docs/agents/*.md`), not anchored to wherever `.agents/skills/diataxis/` or `.claude/skills/diataxis/` happens to be installed. This matters because a skill's own installed directory can itself be distributed to other repos (this skill's source repo, `myskills`, is one such case) — instance state written there would leak into every future install instead of staying local to one project. The blank schema this file is populated from lives at [`../templates/project-context.md`](../templates/project-context.md); that template file is never edited by `setup`, only read.

## Execution

### Step 1: Read Project Metadata

Read the following files (skip gracefully if absent):

1. `package.json` — name, scripts (`format`, `lint`, `test`, `build`, `dev`), dependencies, devDependencies, packageManager field
2. `pnpm-lock.yaml` / `yarn.lock` / `package-lock.json` / `bun.lockb` — determines package manager
3. `CLAUDE.md` — project conventions (logger, auth, data access patterns, format commands)
4. `AGENTS.md` — contributor guidance, commands section

### Step 2: Detect Project Structure

```bash
ls -1
```

Check for:

| Directory present | Inference |
|---|---|
| `apps/` and/or `libs/` | Monorepo |
| `packages/` and/or `services/` | Monorepo |
| Only `src/` at root | Single-package |
| `docs/` | Documentation root exists |

### Step 3: Detect Tech Stack

From `package.json` dependencies, infer:

| Dependency found | Inference |
|---|---|
| `next` | Framework: Next.js |
| `express`, `fastify`, `hono` | Framework: Express/Fastify/Hono |
| `react` | Includes React |
| `tailwindcss` | Includes Tailwind CSS |
| `prisma` | Includes Prisma ORM |
| `vitest` | Test runner: Vitest |
| `jest` | Test runner: Jest |
| `@playwright/test` | E2E: Playwright |
| `typescript` | Language: TypeScript |

### Step 4: Detect Logging Convention

Check `CLAUDE.md` / `AGENTS.md` for a custom logger import. If not found:

- Search for a shared logger in `src/lib/`, `src/utils/`, `lib/`, `utils/` (look for files named `logger.*`)
- If a custom logger exists, note its import path
- Otherwise: "bare `console.log` is acceptable"

### Step 5: Detect Package Namespace

From `package.json` `name` field and `workspaces`:
- If name is `@scope/name`, namespace is `@scope/`
- If workspaces reference `packages/@scope/*`, extract scope
- Otherwise: "none"

### Step 6: Identify Excluded Folders

Folders that are **not** user-facing documentation (should be skipped by Diataxis):

- Common: `.github/`, `node_modules/`, `.claude/`, `.git/`, `docs/agents/` (config written by `setup-my-skills`/`diataxis setup` themselves, not user-facing documentation)
- Project-specific: look for `openspec/`, `specs/`, `audit-reports/`, generated contract folders — list any found

### Step 7: Detect Format Command

Check `package.json` scripts in priority order:
1. `format` → use as-is
2. `lint:fix` → note as format
3. `prettier` → use as-is
4. None found → `npx prettier --write`

### Step 8: Write `docs/agents/diataxis-context.md`

Write the populated file to `docs/agents/diataxis-context.md` (create `docs/agents/` if it doesn't exist yet). Replace all `<placeholder>` values with detected values. For any field that could not be determined, keep the placeholder and flag it in the report.

Use this structure:

```markdown
# Project Context

<!-- Generated by `diataxis setup` on <YYYY-MM-DD>. Lives in this repo at docs/agents/diataxis-context.md — re-run whenever the project structure changes. -->

## Project Identity

- **Name:** `<detected name from package.json>`
- **Description:** `<detected description, or "—" if absent>`

## Package Manager

- **Command:** `<pnpm | npm | yarn | bun>`
- **Format/lint command:** `<detected format command>`
- **Test command:** `<detected test command>`
- **Build command:** `<detected build command>`

## Tech Stack

- **Framework:** `<detected>`
- **Language:** `<TypeScript | JavaScript>`
- **Test runner:** `<detected>`
- **Other key libraries:** `<comma-separated list>`

## Project Structure

- **Type:** `<monorepo | single-package>`
- **App paths:** `<detected or "src/">`
- **Library paths:** `<detected or "none">`
- **Service paths:** `<detected or "none">`

## Logging Convention

- **Use:** `<detected import or "bare console.log is acceptable">`

## Package Namespace

- `<detected or "none">`

## Excluded Folders (not Diataxis territory)

- `<list of detected non-doc folders>`

## Environment Names (if applicable)

- `<detected from CLAUDE.md/AGENTS.md or "not applicable">`

```

### Step 9: Report

Output:

```
diataxis setup complete

Config written to: docs/agents/diataxis-context.md

Detected:
  Project:        <name>
  Package mgr:    <pnpm | npm | yarn | bun>
  Framework:      <detected>
  Language:       <TypeScript | JavaScript>
  Structure:      <monorepo | single-package>
  Logger:         <import or "console.log">
  Namespace:      <@scope/ | none>

⚠ Needs manual input (<N> fields):
  - <field name>: could not be determined — please edit docs/agents/diataxis-context.md
```

## Notes

- Running `setup` again overwrites the existing `docs/agents/diataxis-context.md` — this is safe and intended.
- If `CLAUDE.md` contains a **Commands** section, prefer those over guessing from `package.json` scripts.
- Do not read deep into `node_modules/` or generated output folders.
