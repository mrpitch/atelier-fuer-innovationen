# Sandcastle

Sandcastle runs Claude Code agents inside a Docker container to implement GitHub issues autonomously. This directory holds its configuration.

## Prerequisites

- Docker (via [Colima](https://github.com/abiosoft/colima) on macOS, or Docker Desktop)
- A GitHub personal access token with `repo` scope (or `Contents: Read` for fine-grained tokens)
- A Claude Code OAuth token (`claude setup-token`) or an Anthropic API key

---

## How authentication works

`@mrpitch/sandcastle` lives in a private GitHub repository. Two separate things need to authenticate against that repo:

1. **Host-side `pnpm install`** — when you first add the package or when any developer runs `pnpm install` on a fresh clone.
2. **Docker image build** — the `pnpm install --frozen-lockfile` step inside the container needs to clone the same package from GitHub.

Both use a GitHub personal access token. The token is never stored in `package.json`, the lockfile, or image layers — it lives in `~/.gitconfig` on developer machines and is passed as a BuildKit secret during Docker builds.

---

## 1. Host install — add `@mrpitch/sandcastle` to the project

Generate a token at <https://github.com/settings/tokens>:

- Classic token: `repo` scope
- Fine-grained token: `Contents: Read` on the `mrpitch/myskills` repository

**One-time git credential setup** — configure git to rewrite `github.com` HTTPS URLs to include your token. This lives in `~/.gitconfig`, not in the repo:

```bash
git config --global url."https://YOUR_GITHUB_TOKEN@github.com/".insteadOf "https://github.com/"
```

With that in place, add the package using a clean URL (no token in the URL itself):

```bash
pnpm add "git+https://github.com/mrpitch/myskills.git#path:packages/sandcastle"
```

The resulting `package.json` entry is token-free:

```json
"@mrpitch/sandcastle": "git+https://github.com/mrpitch/myskills.git#path:packages/sandcastle"
```

`pnpm-lock.yaml` stores only the resolved commit hash — also no token. Git uses the `insteadOf` rewrite transparently to authenticate when cloning.

Each developer who clones this repo needs to run the same `git config --global` command once with their own token before running `pnpm install`.

---

## 2. Docker image build — token as a BuildKit secret

The `pnpm install --frozen-lockfile` step inside the container needs to resolve `@mrpitch/sandcastle` from GitHub. The token must be available during this step, but **must not be baked into the image** — a layer that contains a token can be extracted from the image forever, even after the layer is overwritten.

The solution is a BuildKit secret mount: the token is injected into a single `RUN` instruction and is never written to any layer.

### 2a. Update the `sandcastle:build` script in `package.json`

Add `--secret id=github_token,env=GITHUB_TOKEN` to the build command:

```json
"sandcastle:build": "DOCKER_BUILDKIT=1 docker build --secret id=github_token,env=GITHUB_TOKEN --build-arg AGENT_UID=$(id -u) --build-arg AGENT_GID=$(id -g) -t sandcastle -f .sandcastle/Dockerfile ."
```

### 2b. Update the install `RUN` step in `.sandcastle/Dockerfile`

Replace the placeholder install command (generated by `setup-my-skills` as `RUN REPLACE_WITH_INSTALL_COMMAND`) with:

```dockerfile
RUN --mount=type=secret,id=github_token \
  git config --global url."https://$(cat /run/secrets/github_token)@github.com/".insteadOf "https://github.com/" \
  && pnpm install --frozen-lockfile \
  && git config --global --unset url."https://$(cat /run/secrets/github_token)@github.com/".insteadOf
```

This pattern:
1. Reads the token from the secret mount at `/run/secrets/github_token`
2. Configures git to rewrite `https://github.com/` URLs to include the token — so `pnpm install` can clone the git dependency
3. Runs the install
4. Removes the git credential rewrite — the token is gone from git config before the layer is committed

### 2c. Build the image

```bash
GITHUB_TOKEN=your_token pnpm run sandcastle:build
```

`GITHUB_TOKEN` is read from your shell environment by the `--secret id=github_token,env=GITHUB_TOKEN` flag and forwarded to the `RUN` step. It is never written to a layer.

## 3. Sandbox environment — `.sandcastle/.env`

The `.env` file is for **runtime** secrets loaded into the running container — not for the image build. Copy `.sandcastle/.env.example` to `.sandcastle/.env` and fill in the values:

```bash
cp .sandcastle/.env.example .sandcastle/.env
```

At minimum you need one of:

- `CLAUDE_CODE_OAUTH_TOKEN` — get one by running `claude setup-token` on your host
- `ANTHROPIC_API_KEY` — an Anthropic API key

On macOS with Colima, also set:

```bash
DOCKER_HOST=unix:///Users/<your-username>/.colima/default/docker.sock
```

`.sandcastle/.env` is excluded from git via `.sandcastle/.gitignore`.

---

## 4. Running sandcastle

Start Colima before any Docker operation:

```bash
colima start
```

Build the image (first time and after Dockerfile changes):

```bash
GITHUB_TOKEN=your_token pnpm run sandcastle:build
```

Run an agent on a GitHub issue — from a `feat/<issueNumber>-*` branch:

```bash
pnpm run afk <issueNumber>
```

The `afk` script loads `.sandcastle/.env` and passes the issue number to the sandcastle runner. The `sandbox_command` in `docs/agents/implementation-workflow.md` uses this same script via `implement-epic`.

## File map

| File | Purpose |
|---|---|
| `.sandcastle/Dockerfile` | Container image — built once, reused per run |
| `.sandcastle/.env` | Runtime secrets loaded into the container (not in git) |
| `.sandcastle/.env.example` | Template for `.env` — safe to commit |
| `.sandcastle/.gitignore` | Excludes logs, cache, env, and base-branch file |
| `.sandcastle/container-cache/` | Bind-mounted `node_modules` cache between runs |
